SignColors

Introduction

SignColors is a Spigot plugin that lets players with the appropriate permissions add colors and formatting to signs. Write the configurable prefix (default &) followed by a color or formatting code, such as &a or &l.

Features

  • Players can add colors/formats to signs.
  • Permissions per color/format.
  • Use your own color symbol instead of &.
  • Possibility to craft colored signs (recipe and type are configurable).
  • Optional crafted-sign requirement; players can also obtain colored signs from [SC] buy signs or a command.
  • Buy signs require Vault and a compatible economy provider.
  • Colored sign identity is stored in Minecraft item and block data; marked signs retain their identity when dropped through normal block drops.
  • Configurable blocked first lines can help prevent imitation of special signs.
  • Automatically checks for updates (configurable).
  • English and German translations provided and additional can be added manually.

Installation

This guide covers the initial installation and setup.

Download

Make sure to download the correct version of the plugin, fitting the version of the server!

Download the plugin’s JAR file here. Put it into the plugins directory of the server.

Server Start

Start the server. Once it has finished loading, you should find a SignColors folder in the plugins directory.

Configure

Edit plugins/SignColors/config.yml as needed, then use /sc reload or restart the server. See Configuration for the available settings.

To use buy signs, install Vault and a compatible economy provider. Vault is optional for other features.

Configuration

After the first server start, edit plugins/SignColors/config.yml. Apply changes with /sc reload (requires signcolors.command.reload) or restart the server. See Languages for translation files.

Crafting

crafting.enabled defaults to true. When enabled, players need a colored sign to apply codes unless they have signcolors.bypass.crafting. Colored signs can be crafted, bought from an [SC] sign, or given with /sc givesign. When disabled, codes can be applied to ordinary signs; color and formatting permissions still apply.

SettingDefaultDescription
crafting.recipeTypeshapedshaped or shapeless.
crafting.signTypeANY_SIGNResult sign material when the recipe uses a specific sign ingredient.
crafting.amount1Number of colored signs produced by the recipe.
crafting.ingredientsSee example belowMaps ingredient letters to Bukkit material names. ANY_SIGN makes recipes for supported sign types and returns the corresponding type.
crafting.shapeSee example belowUp to three rows for a shaped recipe; spaces represent empty slots. Not used for shapeless recipes.

The default recipe surrounds a sign with four dyes:

crafting:
  enabled: true
  recipeType: shaped
  signType: 'ANY_SIGN'
  amount: 1
  ingredients:
    A: 'RED_DYE'
    B: 'GREEN_DYE'
    C: 'BLUE_DYE'
    D: 'YELLOW_DYE'
    S: 'ANY_SIGN'
  shape:
    - 'A B'
    - ' S '
    - 'C D'

For a shapeless recipe, list the ingredients under distinct keys; their letters and shape do not determine positions. Bukkit permits at most nine ingredients. If no ingredient is ANY_SIGN, set crafting.signType to a supported sign material such as OAK_SIGN.

Colored sign identity is saved in item and block data, not an external database. Signs and items created before the marker-based version are not automatically migrated.

Buy signs require Vault and a Vault-compatible economy provider to make purchases. Their creation and use also require separate permissions. The usage guide explains how to create one.

Usage

Adding colors and formatting

Write the configured prefix (default &) followed by a code before the text, for example &aHello &lworld. You can use multiple codes per line. See Permissions for the available codes and their permission nodes, or use /sc codes to display them in game.

When crafting.enabled is true (the default), use a colored sign obtained from the recipe, a buy sign, or /sc givesign. Players with signcolors.bypass.crafting can use ordinary signs. When crafting is disabled, ordinary signs work for everyone who has the relevant color or formatting permissions.

Creating a buy sign

A player with signcolors.buysign.create can create a sign with these lines:

LineContent
1[SignColors]
2Optional: <amount>:<price>, for example 10:100.0
3Optional: supported sign material, for example OAK_SIGN
4Ignored; the plugin fills this line.

Leave line 2 or 3 blank to use its configured default. The amount must be a positive integer, and the price must be positive and finite. The plugin formats and waxes the completed sign.

Players with signcolors.buysign.use can right-click it to buy colored signs. Purchases require Vault and a compatible economy provider. The configured amount, price, and material can differ from the examples above.

Languages

The plugins comes with built-in English and German translations. More can be added manually.

Adding a custom language

  1. Copy the en_US.properties in the translations folder and name it after your language (e.g. fr.properties).
  2. Adjust the translation values within the file.
  3. Set the language key in the config.yml to your language file code (e.g. fr from the example above).
  4. Reload the plugin or restart the server to make use of the new translations.
